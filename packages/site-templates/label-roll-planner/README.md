# Label roll planner

A browser-local utility for small batch print planning. Inputs are items, labels per item, labels per full roll, full rolls already on hand, and an additional stock allowance. It rounds allowance to whole labels and capacity to whole rolls, and explains those assumptions. It uses no third-party datasets, ad scripts, cookies, or analytics. No user input is transmitted.

Use Node **22.23.4 or newer** (the local verification runtime is Node 24.19.0). Run `npm ci`, `npm run typecheck`, `npm test`, `npm run build`, `npm run e2e`, and `npm audit`. Astro is pinned to **7.4.2**, with its complete transitive graph locked. `npm run dev` binds to loopback only. Automated tests cover arithmetic edge cases, invalid/nonfinite inputs, available stock, fractional buffers, monotonicity, sufficient roll capacity, accessible desktop/mobile interaction, and preview crawl controls. Playwright starts Astro using its own Node executable so an older globally installed npm shim cannot silently select an unsupported runtime.

The previous Astro 6.4.8 pin was removed after CI identified affected Astro/Sharp/esbuild dependencies. Official advisories document the [AVIF optimization RCE fixed in Astro 7.2.8](https://github.com/withastro/astro/security/advisories/GHSA-26w7-cxv4-gfx2) and [base-path authorization mismatch fixed in 7.2.4](https://github.com/withastro/astro/security/advisories/GHSA-376h-93r7-7g6f). This static utility currently uses no image optimization or authorization middleware, but the dependency graph must still clear audit before release. No advisory or audit check is suppressed. [Astro 7.4.2](https://github.com/withastro/astro/releases/tag/astro@7.4.2) raises the Node minimum to include the October 2026 Node security fixes.

This is a **private preview**: noindex metadata and `robots.txt` disallow crawling. `SITEFORGE_SITE_URL` configures canonical and sitemap origin; its default `https://preview.invalid` is a placeholder, not a public deployment. Public production needs real evidence, reviewed content/hosting privacy terms, an exact-commit approval, appropriate robots/canonical configuration, and a separately gated release. Build success does not establish browser accessibility or 72-hour acceptance.
