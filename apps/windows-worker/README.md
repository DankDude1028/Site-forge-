# Outbound Windows worker

Run `./apps/windows-worker/Start-Worker.ps1` from a configured project checkout. `-Once` registers and processes at most one task. A single process runs tasks serially; only one local GPU inference task can run inside it. Do not start a second GPU worker or benchmark concurrently.

Required environment: `SITEFORGE_WORKER_ID` (persistent UUID), `SITEFORGE_WORKER_TOKEN` (short-lived identity-bound token), `SITEFORGE_SUPERVISOR_URL` (TLS origin, or loopback HTTP for local development), `SITEFORGE_ARTIFACT_ROOT` (dedicated artifact directory). Optional `SITEFORGE_WORKER_NAME`, comma-separated `SITEFORGE_WORKER_CAPABILITIES`, and `LM_STUDIO_API_KEY`. The supervisor's token registry must bind the same worker UUID, allowed capabilities and organization, with an expiry of at most 24 hours. Refresh/rotate credentials through operator configuration; never put tokens in a task payload or commit them.

The worker registers, polls for a scoped lease, fetches its checksum-protected checkpoint, starts, checkpoints results, and completes through authenticated HTTP. A background heartbeat renews its fencing token. Uncertain ownership prevents completion; a supervisor later reclaims the expired task. A lost lease response is not retried, avoiding accidentally claiming another task. Retryable local model failures return to the durable supervisor queue. Malformed outputs fail closed. Model responses may produce reviewable proposals but cannot run arbitrary commands or spend money.

Fixture tasks must explicitly include `{"mode":"fixture","site_slug":"label-roll-planner"}`. They read authored assumptions and copy trusted repository source only. This is a useful test workflow, not evidence of actual market demand, successful public publication, or revenue. Build/test the generated source separately using the trusted commands listed in its manifest. Worker code never executes model-provided shell text, installs model-provided dependencies, or receives a generic arbitrary-command job.

For unattended operation, an operator can register `Start-Worker.ps1` as a Windows Scheduled Task under a dedicated restricted account with "restart on failure" and a single-instance policy. Supply secrets through that account's protected environment or secret store. This repository does not auto-install a privileged service, expose LM Studio, or configure inbound firewall access.
